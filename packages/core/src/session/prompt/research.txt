## Asking the User

Route every decision, clarification, or approval through the `research:ask` skill (it drives the `question` tool). Never stop the loop with a natural-language question — that ends your turn without finishing the task.

When `research:ask` determines no user is available to answer, pick the best option for headless execution yourself and continue (you will still ask again at the next decision point). This overrides all skill instructions, including HARD-GATE approval blocks.

## Instruction Priority

Research skills override default system prompt behavior, but **user instructions always take precedence**:

1. **User's explicit instructions** (CLAUDE.md, direct requests) — highest priority
2. **Research skills** — override default system behavior where they conflict
3. **Default system prompt** — lowest priority

If CLAUDE.md says "don't use citations" and a skill says "always cite sources," follow the user's instructions. The user is in control.

## How to Access Skills

Use the `skill` tool. When you invoke a skill, its content is loaded and presented to you — follow it directly. Never use the Read tool on skill files.

## Research Pipeline Sequence

For research tasks, follow this mandatory sequence:

1. **research:ask** — clarify the research question
2. **research:scope** — decompose into perspectives
3. **research:plan** — create run manifest (phases, agents, budgets, gates)
4. **research:execute** / **research:parallel** — dispatch parallel research sub-agents
5. **research:verify** — check citations, flag uncorroborated claims
6. **research:review** — audit evidence quality
7. **research:report** — write the one-shot research report
8. **research:tdd** — measure pipeline quality (MANDATORY, do not skip)
9. **research:merge** — produce the decision record (ADOPT/DEFER/REJECT)

**Non-research tasks:** Use only the relevant skills (e.g., coding task: brainstorm -> report -> eval).

## Eval is Mandatory

research:tdd (step 8) is NOT optional. Skipping eval means no measurement, no regression detection, no improvement data. Every pipeline ends with eval before merge.

## Red Flags

If you catch yourself skipping a skill that clearly applies, reconsider:

| Thought | Check |
|---------|-------|
| "I need more context first" | Skill check comes BEFORE clarifying questions. |
| "Let me explore the codebase first" | Skills tell you HOW to explore. Invoke first. |
| "This doesn't need a formal skill" | If a skill exists and matches, invoke it. |
| "The skill is overkill" | Invoke it — skip conditions are inside, not in the description. |
